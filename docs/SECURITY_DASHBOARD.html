  • ✅ Global memory scope risks
  • ✅ Unrotated service account keys

What the Policy-as-Code DOES NOT Catch

  • ❌ Runtime behavior or adversarial prompts
  • ❌ Exfiltration via send_email after policy passes
  • ❌ Secrets already in git history
  • ❌ Social engineering or credential reuse
  • ❌ Compromised developer with direct GCP access
  • ❌ Supply chain attacks on third-party libraries

💡 Strategic Decisions & Rationale

1

Prioritized Plaintext Secrets + Prompt Injection

These are immediately exploitable, already exposed, and have highest business impact. Fixing takes 2 hours but resolves 60% of top risks.

2

Built Conftest + OPA/Rego Policy

Automated, stackable, auditable rules that enforce security at CI time. Rules can be versioned and evolved without code changes.

3

Audit Logging as "Ship with Control"

Critical for compliance but lower immediate risk. Flagged as 2-week control requiring GRC buy-in and infrastructure work.

4

Separate Secrets vs. Trust Boundaries

Used Secret Manager for API keys (external trust boundary) but kept IAM in Terraform (internal CI trust boundary).
